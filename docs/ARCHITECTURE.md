# 架构与数据设计

## 为什么选择无构建方案

应用不需要服务端、账户和模型推理。原生模块可直接在 GitHub Pages 运行，省去框架、数据库服务与部署适配。源代码就是部署产物，运行网站无需安装 npm 依赖。

## 数据库

数据库 `recall`，schema version 1。仅首次初始化创建默认科目；清空后导入空备份也不会再次插入默认数据。

| Store     | 主键 | 内容                                                                             |
| --------- | ---- | -------------------------------------------------------------------------------- |
| subjects  | id   | 科目名                                                                           |
| questions | id   | 题目、答案、理解、科目 ID、标签、图片、创建/更新时间、到期日期、等级、revision   |
| reviews   | id   | questionId、rating、fromLevel、toLevel、reviewedAt、reviewDay、dueDate、revision |
| meta      | id   | 初始化状态                                                                       |

应用数据完整备份包含前三个 store；meta 是内部初始化状态，导入时重建。主题属于设备偏好，不随学习备份迁移。

查询使用 `getAll()` 读取当前个人错题集合，在内存做筛选和聚合。该选择适合个人级数据；尚未做数万张图片的数据量压力测试。未来数据显著增大时，可增设索引与按需加载图片，但应先设计 schema migration、备份兼容与测试。

## 写入与一致性

- 任何页面只有等 IndexedDB transaction `complete` 才显示保存成功；`abort` 不保留部分写入。
- 复习读取与写入位于同一 `readwrite` 事务，同时覆盖 questions 和 reviews。多个标签页的相同范围写事务由 IndexedDB 串行化。
- reviews.id 为 `questionId:revision`。相同版本的已记录请求返回原记录；不同版本或尚未到期的提交拒绝。
- 编辑提交携带打开表单时的 revision。后台题目更新过则要求重新读取，避免丢失较新进度。
- 删除题目与关联历史同事务；非空科目禁止删除。
- 导出为单个一致只读快照。导入先完整校验，点击两步覆盖确认后同事务清空并写入数据。
- hash 导航重新获取快照；返回焦点时更新只读页面；每 30 秒检查本地日期跨天。

## 图片

只接受 JPEG、PNG、WebP。浏览器解码后使用 Canvas 压缩到 JPEG；透明背景转白色。输出最长边最多 1800 像素、最多 1 MB，最多 4 张/题。最大原文件 15 MB、最大像素 4000 万。浏览器需要先解码图片才能检查像素，因此仍应避免导入来源不明的超大图片。文本作为普通文本渲染，拒绝 SVG 和 HTML 图片类型。

## 日期

ISO 时间戳保存发生时刻；本地 `YYYY-MM-DD` 保存到期日和复习日。日历加天以本地中午构建日期，不按固定 24 小时的毫秒数推进。所有到期比较使用固定宽度日期字符串。

## 备份格式

```json
{
  "format": "recall-backup",
  "version": 1,
  "exportedAt": "2026-10-20T00:00:00.000Z",
  "subjects": [],
  "questions": [],
  "reviews": []
}
```

备份不包含任何账户认证信息。格式升级时应显式增加版本并实现迁移，不能静默接受不认识的版本。现有导入是整体替换，不进行可能引发 ID 冲突的合并。上限见 README；校验不通过时保留原数据库。

## 限制与后续

没有后台通知或自动同步；页面关闭后不会提醒。没有 Service Worker，不承诺断网后首次打开；已加载页面可完成本地操作。未在实际 iPad / iPhone 或 Safari / Firefox 中验证，已做 Chrome 多尺寸检查。不要把 IndexedDB、持久存储授权或一次测试通过视为永久数据保障。
