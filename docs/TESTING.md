1. 本地日期、月末、闰年与跨年。
2. 错题字段、科目、图片格式及数量边界。
3. 搜索题目、答案、理解、标签，以及科目交集筛选。
4. 5 等级 × 3 反馈的全部 15 种组合与变化后的间隔。
5. 复习跨年、闰年与日历日期。

7. 完整 JSON 无损往返。

9. 孤立引用、重复 ID、恶意图片、无效日期和调度不一致。

## 环境与复现

本地使用 Node.js 24、Playwright 1.62.1 和 macOS 上的 Google Chrome。测试入口不依赖这些工具在机器上的具体路径；可按 README 安装依赖和 Playwright Chromium 后运行。项目运行推荐 Node.js 22+。

```sh
npm install
npx playwright install chromium
npm test
# 单独终端启动 npm start
npm run test:browser
```

阶段门槛可通过 `RECALL_PHASE=1`、`2`、`3` 运行阶段子集。未设置则运行全部。GitHub Actions 检查与 Pages 工作流已成功执行。2026-10-20 在正式 Pages 地址重新运行全部 20 项浏览器检查，全部通过，未捕获页面异常；8 个静态资源检查通过。详见 [线上验证记录](ONLINE-VERIFICATION.md)。

## 发布回归中的时序修复

最终文档提交的 [远程检查 #2](https://github.com/cym7777/Recall/actions/runs/39369090427) 暴露了一处测试时序问题：切换到错题库后，在异步页面加载完成前读取了卡片数量，导致取消删除检查比较了错误的初始值。修复为等待卡片出现后再记录数量，并明确断言初始有 2 道题；六页面截图和响应式检查也改为等待各自的准确页面标题，保留原有检查范围。

修复后在正式 Pages 地址再次运行全部 20 项浏览器检查，全部通过，未捕获页面异常。远程检查未通过的历史保留在 Actions 中，不将失败运行计为通过。

## 未验证范围

- 实体 iPad、iPhone、Safari、Firefox；现有手机与 iPad 结论仅为桌面 Chrome 的视口检查。
- 设备真实磁盘耗尽、浏览器自动回收与浏览器损坏；配额失败检查为事务中主动注入异常。
- 数万题、大量图片与接近导入文件上限的性能压力。
- 全球不同网络区域的访问质量；线上功能验证使用现有代理完成。

IndexedDB 持久化仍需配合定期导出备份，测试不能替代备份。
